# Charles Thorn · Portfolio

One-page portfolio for internship applications. Plain HTML, CSS and a few small JS modules. No framework, no build step.

Live: https://aftermaxth.github.io/portfolio/

## Run locally

```
python3 -m http.server 8000
```

Then open http://localhost:8000. The JS modules need a server, so opening `index.html` straight from disk won't run them (the page still renders).

## Structure

```
index.html              the page
404.html                GitHub Pages error page
css/tokens.css          design tokens only (color, type, space, radius, motion) + @font-face
css/base.css            reset and element defaults
css/layout.css          container, section rhythm, 12-column grid
css/components.css      header, hero, telemetry, project, spec, figure, next-card, footer
css/utilities.css       a few single-purpose helpers
js/main.js              loads the hero modules, reveal on scroll, active nav link
js/hero-engine.js       WebGL setup, layout sync, motion controls for the hero
js/hero-shaders.js      the GLSL that draws and animates the engine, plume and contours
js/hero-plume.js        plume geometry (generated by tools/extract_hero.py)
js/heat-text.js         colors the hero intro by its distance from the engine
assets/fonts/           self-hosted Anybody, Archivo and DM Mono (all variable or static WOFF2), with licenses
assets/img/hero/        engine, flame and glow layers cut from the test-cell photo, plus the Mach-number contours
assets/img/             project figures, one folder per project
assets/resume/          Thorn_Charles_Resume.pdf
tools/extract_hero.py   builds the hero layers from the source photo
tools/mach_field.py     draws the Mach-number contour layer
tools/source/           the original photo
tools/og-image.html     source for og-image.png (the link preview)
```

CSS load order is set with `@layer reset, tokens, base, layout, components, utilities;` so nothing needs `!important` outside the reduced-motion reset. Class names are BEM-lite (`project__title`, `project--flip`). Every color and size comes from `tokens.css`, and the hero shader reads its background and grid values from the same tokens.

## The hero

The engine photo is split into three layers by `tools/extract_hero.py`:

- **engine.webp**: the engine and upper test stand, cut out along a hand-traced outline, with the stand fading out before the floor.
- **flame.webp**: the plume as pure emitted light. For each column the script estimates the augmenter wall behind the plume from the bands above and below it, and subtracts it in linear light. Local contrast along the flow axis brings out the shock diamonds.
- **bloom.webp**: a blurred copy of the plume for the glow.

Behind them, `tools/mach_field.py` draws **mach-field.webp**: Mach-number contours in the style of a solver's contour plot (16 bands of the jet colormap, lines on the band edges). It's an illustrative model, not a simulation of this engine, and the legend on the page says so. It follows the structure of an underexpanded jet: a supersonic core that narrows, a shear layer that spreads, and lozenge-shaped shock cells whose spacing was measured from the photo (about 240 px at the nozzle, shrinking downstream). The shocks cross on the axis at the photo's bright spots, since the gas glows hottest just behind them. If you run your own nozzle case in Ansys, the same layer can be rebuilt from exported data.

The page shows those layers as plain images first (with `mix-blend-mode: screen` for the light), so the hero is complete without JS. `js/hero-engine.js` then redraws them in WebGL and animates the plume:

- turbulence carried downstream in the shear layer, growing with distance from the nozzle
- shock diamonds that hold their positions and shimmer in place
- flicker, with the nozzle picking up the light
- a tail that breaks up as it dissipates
- heat haze that bends the background grid and the contour lines around the exhaust

The canvas measures where the static images sit and draws exactly on top of them, so the swap is invisible. The animation pauses when the hero is offscreen or the tab is hidden, and has a pause button. It starts paused when the visitor's system asks for reduced motion. If WebGL isn't available, the static layers stay.

The intro text under the name is colored like a temperature field: `js/heat-text.js` finds the point on the top edge of the flame and engine closest to the text, and the CSS gradient runs from red on the nearest words to blue on the farthest. It recalculates when the layout changes. Without JS it falls back to warm along the bottom. The six colors are lighter than a solver's pure red and blue so every one keeps at least 6:1 contrast.

To rebuild the layers after changing the extraction:

```
pip install numpy pillow scipy matplotlib
python3 tools/extract_hero.py            # add --preview to also write a flattened preview
python3 tools/mach_field.py              # run after extract_hero.py; it reads js/hero-plume.js
```

## Design decisions

- Dark "test cell at night" theme: graphite surfaces and one afterburner-orange accent `#FF8100`.
- Anybody Black Italic at 150% width for the name, section titles and header; Anybody Bold upright for project titles; Archivo for text; DM Mono only for labels and numbers.
- Hairline rules instead of shadows. Square-ish corners.
- Every project uses the same template: eyebrow, title, one-line result, Role / Tools / Timeline / Result spec block, figures, short notes.
- The site works with JS off. JS only adds the hero animation, a one-time fade-in and the active nav state.
